## 2. Logic Chain
1. GitHub Pages project sites host content under subpaths (`https://<user>.github.io/<repo>/`). Root-relative paths (`/css/...`) break under this setup. Therefore, `validate_links.py` and `test_server.py` enforce strict relative paths (`./`, `../`) and simulate subdirectory serving.
2. Windows filesystem is case-insensitive, whereas GitHub Pages (Linux) is case-sensitive. `validate_links.py` incorporates physical directory traversal via `os.listdir()` to verify exact character-by-character casing for all local file references.
3. The New PASONA marketing framework requires 7 continuous logical stages. `validate_pasona_dom.py` and `run_all_tests.py` verify the presence and semantic markup of all 7 sections along with Matsutake 3-tier pricing, Before/After comparison, and dual CTAs (Web booking modal + Official LINE).
4. All test scripts are built with Python standard library modules (`http.server`, `urllib.request`, `html.parser`, `re`, `socket`, `threading`, `pathlib`), guaranteeing zero external dependencies and immediate portability across local and CI/CD environments.

## 3. Caveats
- The test suite is designed to validate HTML, CSS, and JS files as they are generated by worker agents. If files are not yet created when the runner executes, tests will output clear failure diagnostics specifying which files and sections are missing.
- When implementation is completed by `worker_portal_1` and `worker_aesthetic_1`, running `python tests/run_all_tests.py` will validate 100% compliance across all 4 tiers.

## 1. 概要と検証基本方針 (Executive Summary & Philosophy)

本プロジェクトは、GitHub Pages（プロジェクトサイト：`https://<username>.github.io/<repo>/`）での完全静的配信に対応した「業種別LPサンプル集トップポータル（`index.html`）」および「新PASONAの法則に基づくエステサロン向けLP（`samples/aesthetic/index.html`）」の品質保証（QA）インフラを定義します。

### 1.1 基本方針（3大原則）
1. **完全ゼロ外部ランタイム依存（Zero-Runtime-Breakage）**:
   ビルドステップ（Webpack/Vite/Node）がなくても単体で即座に動作し、標準のPython（3.8+）標準ライブラリのみで完結する自動テストハーネスを構築する。
2. **厳格な相対パス保証（Strict Relative Integrity）**:
   GitHub Pagesのルート（`https://example.com/`）およびサブディレクトリ（`https://username.github.io/repo/`）の双方で、1つのリンク切れやアセット欠損（404）も出さない静的リンク検証を実施する。
3. **4-Tier テストピラミッドによる多層的品質検証**:
   単なるリンク確認にとどまらず、新PASONA構成の網羅性、DOM/SEO/アクセシビリティセマンティクス、インタラクティブUI（フィルタ/アコーディオン/追従CTA）、実世界ユーザーシナリオまでを網羅的に自動検証する。

## 2. 静的ホスティング検証アーキテクチャ (Static Hosting Verification)

### 2.1 課題とアーキテクチャ設計
GitHub Pages（プロジェクトサイト）では、配信URLが `/` ではなく `/<repo_name>/` となるため、絶対パス（例: `/css/style.css` や `/samples/...`）を用いると404エラーが発生します。
本検証インフラでは、Python標準の `http.server` と `urllib` を用いて、ローカル環境で「ルート配信」と「サブディレクトリ配信」の両方をシミュレートするテストランナーを定義します。

```
┌─────────────────────────────────────────────────────────────┐
│                 Python Test Runner Harness                  │
│                     (tests/test_server.py)                  │
└──────────────────────────────┬──────────────────────────────┘
                               │
                ┌──────────────┴──────────────┐
                ▼                             ▼
   [Mode A: Root Hosting]        [Mode B: Subdirectory Hosting]
   http://127.0.0.1:8080/        http://127.0.0.1:8080/sample-repo/
   (Map to project root `.`)     (Simulate GitHub Pages subpath)
                │                             │
                └──────────────┬──────────────┘
                               ▼
        ┌─────────────────────────────────────────────┐
        │  Automated HTTP Crawler & Status Assertions │
        │  - GET index.html (200 OK, text/html)       │
        │  - GET samples/aesthetic/index.html (200 OK)│
        │  - GET css/style.css (200 OK, text/css)     │
        │  - Assert 0 404s, 0 500s, 0 Root Redirects  │
        └─────────────────────────────────────────────┘
```

### 2.2 テストサーバーランナー仕様 (`tests/test_server.py`)
- **ポート割り当て**: 動的ポート（デフォルト: `8080`、使用中の場合は `8081-8090` に自動フォールバック）。
- **バックグラウンド起動 & 自動終了**: スレッド/サブプロセスで起動し、HTTPテスト完了後に確実にソケットを解放・シャットダウン。
- **検証項目**:
  - 各ページの HTTP Status Code が `200` であること。
  - レスポンスヘッダーの `Content-Type` が正確であること（HTML: `text/html; charset=utf-8`、CSS: `text/css`、JS: `application/javascript`、SVG: `image/svg+xml`）。
  - レスポンスボディに余計な絶対パスリダイレクトやプロトコルエラーが含まれないこと。

## 3. 相対パス・リンク・アセット検証仕様 (Link & Asset Validator)

### 3.1 検出ルールと厳格基準 (`tests/validate_links.py`)

HTMLおよびCSSファイルを静的解析し、以下の4つのルールを100%パスすることを保証します。

| ルール番号 | チェック項目 | 検出ロジック・正規表現 | 判定基準 |
| :--- | :--- | :--- | :--- |
| **Rule-L1** | **ルート相対パスの完全禁止** | `(?:href\|src\|action)\s*=\s*["']/(?!/)`<br>`url\(\s*["']?/(?!/)` | 先頭が `/` で始まるパスは**即時FAIL**（GitHub Pagesで壊れるため）。`./` または `../` または ファイル名直接のみ許可。 |
| **Rule-L2** | **ローカルファイル実在性検証** | 各相対パスを起点ファイルのディレクトリ基準で `os.path.abspath` 解決 | 参照先ファイルがディスク上に実在しない場合は**即時FAIL**（大文字小文字の完全一致チェック含む）。 |
| **Rule-L3** | **ページ内アンカーID整合性** | `#([a-zA-Z0-9_-]+)` を抽出 → ターゲットHTML内の `id="..."` を走査 | リンク先ページに対象IDの要素が存在しない場合は**即時FAIL**（例: `#offer` へのリンクに対し `id="offer"` が存在するか）。 |
| **Rule-L4** | **外部プロトコル・スキーム検証** | `https://`, `http://`, `line://`, `tel:`, `mailto:` のホワイトリスト判定 | 構文不正なURLや未定義プロトコルを検出。外部アセット（Google Fonts等）のURLフォーマット整合性を確認。 |

### 3.2 大文字小文字厳格チェック (Case Sensitivity Guard)
Windows環境のローカル検証では `Image.png` と `image.png` が同一視されますが、GitHub Pages（Linuxサーバー）にデプロイした瞬間に404になります。
本バリデータは、`os.listdir()` による物理ファイル名走査を行い、**大文字・小文字が1文字でも異なる参照をCI段階で弾く安全機構**を組み込みます。

### 4.2 見出し階層（H1〜H6）およびアクセシビリティ検証
- **H1の唯一性**: 1ページにつき `<h1>` が厳密に1つだけ存在すること（ポータル、エステLP共）。
- **見出しレベルの連続性**: `<h1>` の直下に `<h3>` が来るような階層飛び（Skipped Heading Level）を禁止。
- **画像アクセシビリティ**: 全ての `<img>` タグに空でない有意な `alt` 属性（装飾用画像の場合は `alt=""` と `aria-hidden="true"`）が存在すること。
- **メタタグ & SEO/OGP**:
  - `<meta name="viewport" content="width=device-width, initial-scale=1.0">` の存在。
  - `<html lang="ja">` の設定。
  - `<title>` および `<meta name="description">` の設定（文字数適切性確認）。
  - OGPタグ（`og:title`, `og:description`, `og:type`, `og:url`, `og:image`）の完全性。

## 5. インタラクティブUI・レスポンシブ検証仕様 (Interactive UI & Responsive)

### 5.1 対象コンポーネントと検証項目 (`tests/test_interactive_ui.py`)

#### ① ポータルカテゴリフィルタ機能 (`index.html`)

#### ② FAQアコーディオン開閉ロジック (`samples/aesthetic/index.html`)

  - 展開状態に応じて `aria-expanded="true"` / `false` が正しくトグルされること。

- **テスト内容**:

  - デスクトップ画面（幅1024px以上）では非表示または適切なヘッダーCTAに切り替わること。
